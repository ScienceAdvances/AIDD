# 综合实战：把计算输出整理为研究简报与验证计划

> 本文对应网站教案的 Debian 版本。仓库练习请先读同目录 [README](README.md)：其中命令使用本仓库目录和可配置工具路径；正文的运行命令已按仓库路径调整；多工具任务统一通过可配置入口执行。


你现在已经见过几种很不一样的结果：一个对接模型有很低的分数，一条序列有较低的 NLL，一段轨迹有较小的 RMSD，一个 CAR 构建有较低的无刺激背景。这些结果分别描述结构、序列、动态变化和细胞响应，需要放回各自的问题中解释。

这一课把前面的内容连起来。我们练习怎样根据已有结果作出研究决定。

## 1. 本课实战：把前面几章变成可追溯的研究简报

前面的章节各自产生了文件：对接模型表、序列候选表、轨迹摘要，以及 CAR-T 的面板汇总。这一课把它们整理成一份简报，练习每句话怎样由具体数据支撑，以及下一轮验证为什么这样安排。

先认清输入的角色：

先从 HADDOCK 的逐阶段与最终模型表读取采样数量、分数和参考结构质量，区分“是否出现好姿态”和“排序是否保留它”。本轮完整运行的阶段信息位于 `examples/debian13_20261023/haddock_analysis/`，解释时对应 full 与 smoke 各自的配置。

序列部分读取 `candidates.csv`、`shortlist.csv`，追踪统一评分和提名理由；MD 读取 `analysis_summary.json`，同时带上 Factor Xa 的体系身份与轨迹时长；CAR-T 读取 `panel_summary.csv`，保留面板、实验终点和分母。GNINA 的执行记录与对照表则用于交代六次真实对接、评分模式和参考 RMSD。这些输入组成证据来源，不能混成同一个分子的验证链。


它们分别来自不同研究问题。写简报时，先交代各自体系和指标，再提炼共同的判断方法。这样既能讲清一项工作的过程，也能说明方法怎样迁移。

### 1.1 运行简报生成程序

简报程序使用 Python 标准库。在教材根目录执行；初次练习可以直接读取已保存的公开案例结果：

```bash
cd '.'
python scripts/build_case_brief.py --output runs/integrated/my_case_brief
```

若前面已经运行了自己的计算，可显式选择这些结果。例如第 3、4、6 章的目录分别使用本章之前示例中的名称时：

```bash
python scripts/build_case_brief.py \
  --sequence-run runs/06_my_optimization \
  --cart-run runs/04_my_cart \
  --md-analysis runs/03_my_md_analysis/analysis_summary.json \
  --gnina-run workflows/gnina/my_dry_run \
  --output runs/integrated/my_new_case_brief
```

各参数对应输入表所在的目录或摘要文件，输出使用新目录。GNINA 若在另一台机器运行，把完整任务目录复制回来，并把 `--gnina-run` 指向它。

程序读取实际表格，提取关键指标、来源和解释范围，再为每个提名序列写出待检验假设。它生成四份材料：

程序首先写出 `evidence.csv`，为每个数值保存定义、单位、来源和下一步；再用 `candidate_validation_plan.csv` 把 WT 与变体的提名理由连接到结构、制备和结合检查。随后生成可编辑的 `brief.md`，作为英文研究简报骨架；`build_summary.json` 记录实际读取的结果及输出数量，帮助发现输入串用。


### 1.2 亲手从一行候选生成一句结论

下面读取本章默认使用的序列结果，选择 L9K，核对它相对 WT 的模型分数变化：

```bash
python - <<'PY'
import csv
from pathlib import Path

run = Path('examples/debian13_20261023/sequence_debian_only')
rows = list(csv.DictReader((run / 'candidates.csv').open()))
wt = next(row for row in rows if row['candidate_id'] == 'WT')
variant = next(row for row in rows if row['candidate_id'] == 'single_L9K')
change = float(variant['mpnn_nll_mean']) - float(wt['mpnn_nll_mean'])
print('Candidate:', variant['sequence'])
print('NLL change versus WT:', round(change, 4))
print('GRAVY:', variant['gravy'])
print('Selected:', variant['shortlisted'])
PY
```

NLL 差值约为 **−0.1401**。据此可以写：“L9K 在共同八组解码顺序下，平均 NLL 比 WT 低约 0.1401，GRAVY 也降低；它作为一个局部替换假设进入本轮提名。接下来检查热点几何、制备性质及同条件结合表现。”

这句话同时包含比较对象、评价协议、具体观察和下一步。接下来的章节解释，为什么还需要从结构判断继续走向性质、结合和功能。

## 2. 从结构合理，到功能有效，中间还有几层问题

假设你从序列优化里提名了 L9K。模型 NLL 下降，GRAVY 也下降。现在你确实可以提出：这条序列在当前模型下与骨架相容，并且平均疏水性代理降低。

接着要问：它实际能否制备，是否采用预期构象，是否仍以合理方式识别目标？即使这些问题都得到支持，还要问在所需环境中有没有足够暴露、是否具备选择性，以及目标作用能否转化为功能。

对于 MDM2 这样的胞内靶点，还需要确认分子能否到达相应细胞位置。对于 CAR，识别头还必须在完整膜蛋白构建和细胞环境中工作。因此，从结构计算推进到功能评价，需要依次回答这些问题，并为每一步补充相应证据。

用这条链看回已有案例，就容易理解为什么我们分别保留“设计”“再预测”“过滤”“结合”“功能”的状态。每一步的结果为下一步提供选择依据，逐渐形成完整的证据链。

可以把这条过程理解为逐层减少不确定性。结构模型先提出“也许能以这种方式接触”；重新预测检查这种接触是否依赖生成时强加的条件；结合实验再检验分子是否确实识别目标；功能实验判断识别是否转化为需要的生物学变化。前一层通过，增加继续研究的理由，但后一层仍可能失败。

因此，本套案例共同提供的是研究方法训练。Factor Xa 的轨迹不能验证 L9K 的动态稳定性，官方小分子亲和力输出也不能给 p53 肽赋予活性。方法可以迁移，证据必须跟着具体分子、构建体与条件走。

## 3. 亲和力到底表示什么

在简单的一对一结合模型中，可以写出：

$$P+L\rightleftharpoons PL$$

P 和 L 分别代表两个结合对象，PL 是复合物。关联速率常数记作 kon，解离速率常数记作 koff；在这个模型适用且条件一致时，Kd=koff/kon。较低 Kd 表示平衡下较高的亲和力。

这也说明，相同 Kd 未必对应相同的结合和解离速度。若问题关心结合维持时间，单报 Kd 可能还不够。这些动力学参数由相应的时间分辨测定和拟合模型确定。

IC50 和 EC50 则描述特定测定里的半最大抑制或响应浓度，会依赖实验条件和机制。解释这些效应指标时，需要同时说明测定条件及其与结合过程的关系。CAR 表面 MFI、IFN-γ 与靶细胞存活又是不同读数，理解其测量对象比记住“越大越好”更重要。

将平衡常数与标准结合自由能联系起来，需要具有明确物理定义的自由能。前面的 HADDOCK 分数是加权排序函数，ProteinMPNN NLL 是概率评价，GNINA 的预测也有各自适用范围。从模型分数估计亲和力，需要先用相关体系建立并验证映射关系。

在这个一对一平衡模型中，也可写成 $K_d=[P][L]/[PL]$。方括号表示平衡浓度：同样的游离浓度下，形成的复合物越多，Kd 越小。在游离配体近似充足、模型适用的条件下，占据比例约为 $[L]/(K_d+[L])$；当游离配体浓度等于 Kd 时，占据比例约为一半。这个关系使“亲和力”有了具体实验含义。

这里的条件很关键。多价结合、协同作用、配体耗竭或膜上受限扩散可能使简单模型不再适用。即使得到很低的 Kd，也仍需检查选择性、达到作用位置的浓度和作用持续时间。因此，研究简报应把结合终点与功能终点分别写清，再解释二者可能怎样连接。

## 4. 怎样写一个有用的负结果

回到本轮 BoltzGen VHH 案例：两个候选都没有通过全部筛选，整体 RMSD 分别为 24.17 和 22.46 Å，binder 自身 RMSD 却约为 1.33–1.39 Å。主要问题集中在复合物几何一致性。

一条可复查的负结果应包含输入和采样规模、实际筛选标志、失败项以及下一轮假设。最终排名有两行，并不表示两条合格。ESMFold2 保留待办，也没有结合实验。[本轮完整解释](../15_boltzgen/tutorial.md)。

负结果的价值在于缩小下一轮的问题。本轮 BoltzGen 的 binder 自身形状较接近设计，而复合物一致性差，优先需要检查相对摆放；如果下一轮只优化单体局部能量，就没有直接针对当前失败项。一个有用的实验或计算对照，应能让两种解释产生不同的预期结果，帮助决定后续资源投向。

## 5. 如果数据要进入模型，怎样避免看起来很准

设想你整理了一批同一母序列的单点变体，然后随机分成训练和测试。测试集里的序列可能与训练集只差一个氨基酸。这样的测试主要评价模型在相近序列附近的插值能力。新家族、新骨架或新靶点上的表现需要用对应的独立测试集检验。

所以划分方法要从预期应用倒推：你到底希望预测同一个骨架附近的变体，还是完全新的识别头？如果是后者，可能需要按序列相似性、结构、靶点或实验批次分组，避免高度相关样本跨组泄漏。划分方法应与预期使用场景一致。

标签本身也要检查。把不同测定的 MFI、Kd、杀伤率不加区分地混成一个“活性”标签，模型即使拟合得好，也可能在学习实验差异。未测定的候选标为缺失，低于检测下限的结果按截尾或区间信息记录。来源、条件、缺失原因和重复身份，都是数据的一部分。

这与 CAR-T 源数据练习是一回事：先弄清每个数字的出处和含义，才谈训练或统计。这一节为后续性质模型的训练与评价设计打基础。

## 6. 如果只能验证少量候选，怎样选

先问这批验证要获得什么信息：确认某个局部替换是否有益，比较两个机制，还是寻找不同序列区域的机会？然后围绕这个问题安排基线、对照和候选。

序列优化里，我们保留 WT，选 D5E、S4E、L9K，让不同位置的假设都有机会被检验。L9R 没有进入这一轮，是因为当前多样性规则优先保留不同位置的变化。如果下一轮专门想理解第 9 位的 K 与 R 差别，就可以重新安排二者的配对比较。

如果有 12 个名额，可以把一部分用于基线与必要对照，一部分用于已过基本复核的优先候选，再留一部分区分关键假设或探索不同簇。数量应由测定和研究问题决定。所谓主动学习，是利用新获得的数据更新下一轮选择；选择时可以同时考虑预测表现、不确定性和新样本可能提供的信息。

## 7. 把计算案例讲成一段完整经历

先说明你在解决什么问题，再讲为什么选择当前方法。之后只展示最能支撑结论的一张图或一张表，解释你做过的具体检查，最后提出尚缺的证据和下一步。读者或面试官应能顺着这条因果关系走下来。

例如，多肽案例可以从“怎样利用结构提出受约束变体”开始。接着用 HADDOCK 的排序反例说明为什么不能只看第一名，用固定热点的 ProteinMPNN 设计解释候选来源，再用 197→176→5→4 展示筛选逻辑。结尾讨论结构、结合及功能验证。关键参数在解释方法选择时再展开。

个人贡献也要具体。你亲自读取并复算结果，可以说完成了结果分析；只学习了已保存输出，就说明学习和核对了什么。讲清自己采取的行动、核对的结果和形成的判断，就能让听者理解这份工作的价值。
